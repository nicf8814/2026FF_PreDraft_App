# FWHFFL 2026 Draft Kit — Framework (v2.0, reconstructed)

> **Provenance note:** `src/fwhffl_pipeline_original_reference.py` opens by declaring
> itself an implementation of "DRAFT_KIT_FRAMEWORK.md v2.0" — but no such document
> existed anywhere in the source project's files. This document reconstructs that spec
> **from the working code itself**, since the code is the only surviving source of
> truth for the design. Treat this as a description of what the pipeline *does*, not an
> independently-authored spec the code was built to match. If the original framework
> doc exists somewhere else (an old chat, a different project), replace this file with
> it and diff against the code for drift.

## Design principles (stated in the code's own docstring)

- Games-played assumption = **Option A**: trust FantasyPros' seasonal stat-line blend
  as-is. Season total ÷ 17 is used *only* to bucket players into per-game shrink bands
  — never as a standalone per-game projection.
- Stage 1 shrink factors are a **directional prior**, logged as ESCALATED, because they
  were fitted to Sleeper weekly projections, not the FantasyPros seasonal lines this
  pipeline actually scores under ESPN rules for 2026.
- Auction dollar values are **generated by the model** from VORP, never copied from a
  market sheet. The market/cheat-sheet values are used only as a shape anchor (Stage 5)
  and a Stage 6 pre-keeper baseline — never a direct input to a player's price.
- Never manufacture a projection. Never close a validation finding silently.

## Pipeline overview

```
load_projections()  →  Stage 1  →  Stage 2  →  Stage 3  →  Stage 4  →  Stage 5  →  Stage 6
   (raw stats)        (shrink)   (team env)    (VORP)     (tiers)    ($ values)  (inflation,
                                                                                  keeper-gated)
                                        ↓
                              validate() — 8 passes, runs after Stage 6
```

### Data load

Combines per-position projection files (RB/WR/TE "flex" file + separate QB file) into
one dataframe scored under league rules:

```
SeasProj = PaYd*0.05 + PaTD*4 + RuYd*0.15 + RuTD*6 + Rec*0.5 + ReYd*0.15 + ReTD*6
PG_raw   = SeasProj / 17
```

Also parses a market/cheat-sheet CSV into a `{player: $}` dict, used later purely as a
shape anchor — never as an input to VORP or the base value.

### Stage 1 — Calibrate (shrink)

Applies a per-game shrink multiplier by PG_raw band (regression toward the mean, larger
shrink for very-low-volume players):

| PG_raw band | Shrink factor |
|---|---|
| 0–5 | 1.345 (but forced to 1.0 — see caveat below) |
| 5–10 | 0.960 |
| 10–15 | 0.965 |
| 15–20 | 0.954 |
| 20+ | 0.942 |

**Caveat baked into the code:** the <5 PG band's 1.345 inflator is never actually
applied (`df.loc[df.PG_raw < 5, "shrink"] = 1.0`) — the framework doc that would have
explained why is missing, but the code comment says it's to avoid letting a small-n
(~80 player) artifact touch real draft boards. Preserve this override if you touch
Stage 1.

Also attaches each position's mean absolute error (MAE) as an uncertainty band, used
later in tiering (Stage 4) and Monte Carlo tier-stability testing (Validation Pass 6).

### Stage 2 — Team environment

Adjusts each player's per-game points by their team's 2025 offensive Points/Game
relative to league average, with two guards:

1. **Regression toward the mean for teams with a new 2026 play-caller** (from a "Coach
   Map" sheet) — a team's raw multiplier is blended 60/40 back toward 1.0
   (`REG_WEIGHT_DEFAULT = 0.6`) so a coaching change doesn't fully inherit the old
   staff's efficiency number.
2. **Half-weight application** (`apply_weight = 0.5`) — because FantasyPros' seasonal
   projections already price in known coaching changes to some degree, applying the
   team-environment multiplier at full strength would double-count that signal.

### Stage 3 — Points → VORP

```
repl     = replacement level for the player's position (see VALIDATED_PARAMETERS.md §2.1)
VORP_pg  = PG_env - repl
VORP_tot = VORP_pg * 17
```

### Stage 4 — Tiering

Within each position, sorted by VORP_pg descending, a new tier starts whenever the gap
to the previous player exceeds **half that position's MAE**. This ties tier breaks to
the actual noise floor of the projections rather than an arbitrary dollar gap — a tier
break has to be bigger than the uncertainty in the underlying numbers to count as real.

### Stage 5 — VORP → dollars

- Priced pool = top `POOL_SIZE` players by VORP_tot (`TEAMS * ROSTER` = 156 for a
  12-team/13-roster league); everyone below that line is priced at $0 (waiver-add
  territory).
- Each pool player gets a $1 floor; the remaining budget surplus
  (`BUDGET − POOL_SIZE`) is distributed proportional to `VORP_tot ** exponent`.
- The exponent is chosen automatically (searched 0.5–1.2 in 0.02 steps) so the #1
  overall player's price lands close to the market cheat-sheet's own top-3 average —
  this is the only place the market sheet touches the model, and only as a *shape*
  target, not a value input.
- Final reconciliation nudges the largest/smallest values by $1 increments until the
  pool sums to exactly `BUDGET` ($2,400).

### Stage 6 — Tier/position inflation + keeper repricing (**gated on keepers**)

Two independent effects, both always computed (see bugfix note in the code — tier/
position shape used to be incorrectly gated behind keepers existing; it isn't anymore):

1. **Shape correction** (always applied, keepers or not): blends a tier-based inflation
   curve and a position-based inflation curve (see `VALIDATED_PARAMETERS.md` §2.4) —
   this captures the empirically observed auction-room behavior where studs get bid
   past raw VORP and mid-tier players get squeezed below it.
2. **Keeper budget-reconciliation multiplier** (`base`): only nonzero-effect once
   keepers exist. `base = (BUDGET − sum(keeper salaries)) / (BUDGET − sum(keeper market
   values))` — i.e., how much the open-auction pool needs to inflate/deflate given how
   much real cash keepers pulled out of the market relative to what they'd have cost at
   market value. **Requires 2 confirmed keepers × 12 teams (24 total) with salary and
   market value for each.** Pre-keeper, `base = 1.0` and the board is explicitly
   labeled pending.

Kept players themselves are priced at their actual salary, not a model value, and are
excluded from the open-pool $ sum.

## Validation — 8 passes (`validate()`, runs after Stage 6)

Every check logs `(pass_number, name, severity, disposition, detail)` to a findings
list. Disposition is one of `ACCEPTED`, `CORRECTED`, or `ESCALATED` — **ESCALATED
findings must stay visible in any report**, never silently dropped.

| Pass | Name | Checks |
|---|---|---|
| 1 | Input provenance | Confirms 2026 seasonal stat lines are present and scored under league settings; notes projection provenance assumption |
| 2 | Structural coverage | Market-priced players missing a projection; separately flags players with a market price but a suspiciously empty/partial stat line (rookie/injury-return defect pattern) |
| 3 | Calibration | Reproduces the Stage 1 shrink bias against held-out prior-season actuals; flags that shrink was fit to weekly Sleeper data, not the seasonal FantasyPros lines actually in use |
| 4 | Committee/volume false positives | Flags any priced RB (Value ≥ $20) whose snap share was below 28 snaps/game the prior season — a genuine part-timer, not a lead back |
| 5 | Role-change false negatives | Surfaces the biggest model-vs-market undervaluations, read as "let the room overpay" signals once Pass 2 coverage gaps are resolved — not treated as errors |
| 6 | Tier stability (Monte Carlo) | Re-ranks the board 300x with per-position MAE noise added to VORP_pg; reports the adjacent-rank flip rate. High flip rate (>25%) is *expected*, not a bug — it's why the output should present as tiers/$ ranges, not precise ranks |
| 7 | Budget & shape reconciliation | Confirms the priced pool sums to exactly $2,400; compares #1 RB/WR values against the current market's own top-3 anchor |
| 8 | Parameter sensitivity | Re-runs Stage 5 at exponent ±0.1 and reports mean absolute dollar movement, to show how much of the board is an artifact of that one tunable |

## Constants that must not silently drift

`BUDGET = 2400`, `TEAMS = 12`, `ROSTER = 13`, `POOL_SIZE = 156`. If the league's roster
rules ever change (see the Article III/IV discrepancy in `LEAGUE_RULES.md`), these need
a deliberate, logged update — not a silent recompute.
